# Telegram-бот NEFOR SPOT

Бот считает стоимость расходников для процедуры, ведёт склад отдельных продуктов и оттенков, записывает все изменения остатков в журнал и позволяет администратору проводить инвентаризацию и выгружать данные прямо в Telegram.

## Роли

- **Мастер**: создаёт расчёты, видит только материалы, разрешённые для калькулятора, и свою историю.
- **Администратор**: пользователь с Telegram ID из `ADMIN_USER_ID` (по умолчанию `7789152483`). Видит склад, закупочные цены, журнал движений, историю всех расчётов и выгрузки.

Мастера не получают данные об остатках, закупочных ценах и внутренних ставках. При изменении ставки старые расчёты сохраняют прежние значения.

## Первичная настройка

1. Создайте Telegram-бота через BotFather и скопируйте выданный токен.
2. В Replit откройте **Tools → Secrets** и добавьте секрет с именем `BOT_TOKEN`. Не отправляйте токен в чат и не записывайте его в файлы проекта.
3. Запустите workflow **NEFOR SPOT Telegram Bot**. При первом запуске бот создаст базу, применит схему, загрузит каталог и исторические остатки и начнёт принимать сообщения.
4. Напишите боту `/start`. Администратор определяется по `ADMIN_USER_ID`; мастерам достаточно открыть бота и нажать Start.

Бот использует polling. Должен работать ровно один процесс с данным токеном. Незавершённый расчёт при перезапуске может потеряться, но не списывает остатки до нажатия «Завершить расчёт».

## Переменные окружения

| Имя | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный секрет Telegram из BotFather; задаётся в Replit Secrets. |
| `ADMIN_USER_ID` | Telegram ID администратора; по умолчанию `7789152483`. |
| `DATABASE_PATH` | Путь к SQLite-файлу; по умолчанию `data/nefor_spot.sqlite3`. |
| `DATABASE_URL` | Необязательный SQLite URL, например `sqlite:///./data/nefor_spot.sqlite3`. Если задан, имеет приоритет над `DATABASE_PATH`. |
| `APP_ENV` | Название среды; по умолчанию `development`. |
| `LOG_LEVEL` | Уровень логов; по умолчанию `INFO`. Токен никогда не выводится в логи. |

Версия приложения сейчас использует SQLite. PostgreSQL URL намеренно не принимается: для него понадобится отдельный адаптер хранилища.

## База, миграции и резервные копии

- База хранится в `DATABASE_PATH`. Для постоянной эксплуатации путь должен указывать на диск, который сохраняется между перезапусками и обновлениями.
- Схема использует `PRAGMA foreign_keys=ON`, WAL и версию `PRAGMA user_version`. Миграции только вперёд; таблицы с историей не пересоздаются.
- Каталог и стартовые остатки добавляются через стабильные ключи только для отсутствующих записей. Перезапуск не сбрасывает склад и не перезаписывает ставки, изменённые администратором.
- Перед структурным обновлением существующей базы создаётся SQLite backup через штатный API резервного копирования.
- В панели администратора выберите **Резервная копия / экспорт**. Бот отправит файл базы или CSV остатков, движений либо расчётов. Скачайте файл из чата и храните его отдельно от проекта.
- CSV использует кодировку UTF-8 с BOM и разделитель `;`.

### Восстановление базы

1. Остановите единственный процесс бота.
2. Сохраните текущий файл базы отдельно.
3. Замените `data/nefor_spot.sqlite3` выбранной резервной копией через файловый менеджер хоста.
4. Запустите бота и проверьте остатки и историю.

Не заменяйте файл, пока бот работает: сначала остановите worker.

## Тесты

Автоматические тесты используют временную SQLite-базу и проверяют расчёт Decimal, запятую в числах, списание и идемпотентность, откат транзакции, закупку, списание, корректировку, полную инвентаризацию, архивирование, снимки ставок и сохранность данных после повторного запуска.

Запуск тестов:

```sh
uv run python -m unittest discover -s tests -v
```

## Постоянная работа 24/7

Открытый редактор Replit и обычный development workflow не являются постоянным production-хостингом. Для Replit выберите **Reserved VM Deployment** (в Publishing выберите цель VM/Reserved VM) и настройте запуск `uv run python main.py`. По текущей документации Replit Reserved VM требует платный план. Для SQLite укажите путь на постоянном диске этого VM и задайте `BOT_TOKEN` как production secret.

Не выбирайте Autoscale: бот использует long polling и должен постоянно работать как один фоновый процесс. Не создавайте более одного polling worker для одного токена.

Если в аккаунте недоступен Reserved VM, перенесите проект на любой постоянный Linux/Python-хостинг с фоновым worker или управляемым сервисом:

1. загрузите файлы проекта целиком, включая `uv.lock`;
2. укажите Python 3.11+, команду запуска `uv run python main.py` и постоянный путь для базы;
3. добавьте `BOT_TOKEN`, `ADMIN_USER_ID`, `DATABASE_PATH`, `APP_ENV` и `LOG_LEVEL` через защищённую панель хостинга;
4. включите автоматический перезапуск процесса и храните резервные копии отдельно.

Код не зависит от Replit SDK и использует официальный Telegram Bot API через aiogram, поэтому при переносе не требуется менять обработчики. Секрет `BOT_TOKEN` нужно заново добавить в панели нового хостинга.

## Обновление проекта

Зависимости закреплены в `pyproject.toml` и `uv.lock`. Схема обновляется автоматически при старте приложения. Не удаляйте файл базы при обновлении; сделайте резервную копию и используйте тот же постоянный `DATABASE_PATH`.

Для локального запуска с установленным `uv`:

```sh
uv sync --frozen
uv run python main.py
```
